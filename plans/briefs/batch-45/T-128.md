Product principles (PRODUCT.md): 'numbers are heroes' (big, tabular, LTR inside RTL); 'log first, admire
later'; two accents with strict roles (mint `--fs-accent` = action/focus, lime `--fs-signal` =

## What the lead SAW (390px, 18 completed sessions over 6 weeks)
Home shows ZERO training numbers for a returning user: the start CTA, a novice tip ('לחצו על הכפתור
למעלה — בחרו תבנית או אימון ריק...') still shown after 18 sessions, the program card, and an empty week
grid. `WorkoutStreak` and `InsightCard` both self-hide (the streak is DAILY, so a 3x/week lifter reads 0),
and the header subtitle still says 'היום: התחילו אימון מהכפתור למטה'. Progress holds all the numbers;
the most-opened screen tells a trainee nothing about their training.

## Goal
With history, home answers in two seconds: WHAT IS NEXT, HOW IS MY WEEK GOING, AM I PROGRESSING — with
the numbers as the largest type on the page. Zero-session users keep today's `FirstRunHero` unchanged.

## Build (replace, don't pile on)
1. 'This week' hero: sessions completed this week as a BIG numeral against a weekly target (target = the
   active program's sessions/week when a program is active — ProgramCard knows it; otherwise the median
   sessions/week over the last 4 complete weeks; with < 2 weeks of history show the count alone, no
   invented target). Plus ONE progress signal: volume so far this week vs the SAME point of last week as a
   signed % — only when last week has data (never print a number the data does not support). Week
   boundaries must match WeeklyGrid's (check its first day of week).
2. 'Last workout' recap: name (template name if present, else the first exercise's Hebrew name), Hebrew
   relative date (היום / אתמול / שלשום / לפני N ימים — check datetime.ts for a helper first), duration,
   total volume, PR count if the session data already carries PR info (if it needs a DB lookup, skip PRs
   rather than adding a slow query). Tap → `/detail/:id`.
3. ONE 'next workout' block: ProgramCard and TodaysWorkoutCard can both describe what is next — read both
   and make sure a user never sees two competing 'next' blocks; explain the resolution in your report.
4. Retire the novice `CoachMark` once the user has >= 3 completed sessions; give returning users a
   factual header subtitle (e.g. last workout + this week's count). First-run users keep today's copy.
5. `WeeklyGrid` carries rest-day marking — keep that capability (and its tests); you may move/restyle
   its container.
6. Put the stats math in a PURE module in `src/components/dashboard/` (e.g. `homeStats.ts`) with unit
   tests: week boundaries, median target, the %-delta guard, relative-date labels, bilingual-name display.
   No new data fetching beyond what Dashboard already loads.

## Visual rules
Numbers large + `font-variant-numeric: tabular-nums`, wrapped in `dir="ltr"` spans inside RTL text. ONLY
existing tokens (`--fs-*`, `--font-display`, `--font-body`, `--font-mono`, radius/shadow tokens); always
set background and text colour together. No new accent; lime only for a PR mention. Motion none or subtle,
reduced-motion safe. Hebrew copy short, factual, no emoji, no cheerleading. RTL: logical properties
(ms/me/ps/pe/start/end); chevrons point the reading direction.
