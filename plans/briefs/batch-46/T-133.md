## Why (verified by the lead, photo `visual-qa/survey/b-progress.png`, 18 sessions over 6 weeks)
1. **Home and Progress contradict each other under the same word "השבוע".** Home (`src/components/dashboard/homeStats.ts`)
   counts the SUNDAY-based calendar week (`getWeekStart`, same as WeeklyGrid) and sums volume from completed sets
   (`sessionVolume`). Progress (`src/pages/progress/progressMetrics.ts` `summarizeWeeklyVolume` ~:94) counts the
   TRAILING 7 days and sums the stored `s.totalVolume` (older rows may not carry it). On a Monday the same trainee
   reads "1 / 3 השבוע" on Home and "השלמת 3 אימונים השבוע" on Progress.
2. The overview is ~70% empty: a verdict line, one card with three numbers, a collapsed "מתקדם", then nothing.
3. In that card: a bare muted **"0"** under "אימונים" (the `DeltaChip` in `tabs/OverviewTab.tsx` renders a FLAT delta
   as "0" with no sign, icon or meaning); **"+315"** under volume with nothing saying "vs last week"; and **"0 רצף ימים"**
   for someone who trains three times a week (the rest-day-aware daily streak is 0 whenever no rest day is declared).
4. Test noise: `[Analytics] Failed to load progress data TypeError: getWorkoutSessions is not a function`
   (`useProgressData.ts:135`) — a Progress page test (`src/pages/__tests__/Progress.pageShell.test.tsx` or
   `Progress.tablistRtl.test.tsx`) mocks sessionDb without that function, so it silently runs the ERROR path.

## Build, in priority order (land each with tests before starting the next)
1. **One definition of "this week" for the whole app.** Move the pure week math out of the dashboard into a neutral
   module, e.g. `src/utils/trainingWeek.ts`: `weekStartAt`, `sessionsInWeek`/`sessionsThisWeek`, `sessionVolume`,
   `medianSessionsPerWeek`, `weeklyVolumeDeltaPct` (Sunday-based, completed sessions only, completed-set volume).
   `homeStats.ts` imports them from there (its exported names keep working — re-export; its tests stay green).
   The overview's week card, verdict and deltas then read the SAME functions. Grep every caller of
   `summarizeWeeklyVolume` / `weekVerdict` / `weeklyCountDelta` / `weeklyVolumeDelta` first: move trainee-facing
   "השבוע" surfaces to the shared definition; leave coach surfaces exactly as they are (read-only for you). Add a
   test that pins it: same sessions + same `now` → Home's `thisWeek` === the overview's count.
2. **Week card.** אימונים as `X / target` when a target exists (same target rule Home uses: declared program beats
   the median; `null` → just `X`); נפח (ק"ג) with its delta; third number = training time this week (minutes) —
   REMOVE the streak from this card (Home's streak card owns the streak; Progress must not print "0 רצף ימים" to a
   regular lifter). Delta chips: a flat delta renders NOTHING; one short caption under the row says what the deltas
   compare against ("לעומת אותו זמן בשבוע שעבר" or shorter — see Copy). Verdict line reads the same week.
3. **NEW "8 שבועות" trend card** (`src/pages/progress/components/`): sessions per week for the last 8 Sunday-based
   weeks as bars, the weekly target as a reference line when known, and one caption like
   "5 מתוך 8 השבועות האחרונים ביעד". Hidden when fewer than 2 complete weeks of history (never fake zeros). Follow
   the time-axis direction the EXISTING charts in this app use (look at `WorkoutsTab.tsx` / `WeightSection.tsx` /
   `Sparkline.tsx`) — do not invent a new convention. Accessible text summary via the existing `ChartSummary`.
4. **NEW strength snapshot card**: the 3 exercises trained in the most sessions over the last 8 weeks; for each the
   best e1RM of the last 4 weeks and the change vs the 4 weeks before (↑/↓ kg, zone colour; no arrow when there is
   no earlier data). Reuse the e1RM helper the Strength board already uses (`oneRepMax` / `recordE1RM` in
   progressMetrics, `strengthFormat.exerciseLabel` for names). Tapping a row opens that exercise's detail the SAME
   way `StrengthSection.tsx` does. Hidden with < 2 sessions per exercise.
5. **Fix the noisy test**: give the sessionDb mock a `getWorkoutSessions` so the page test exercises the SUCCESS path
   and asserts something visible on it.
Keep: the verdict line, the PR card, the "מתקדם" expander and its contents, the empty state (0 sessions).
